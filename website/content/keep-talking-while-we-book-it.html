Keep talking while we book it

A conversation can move faster than the work it starts. Follow a real Parlora session as the caller asks a question, changes the date, and confirms an appointment while Jido works in the background.

A caller asks for an appointment with Dr. Lee on Wednesday. While the assistant checks the calendar, they ask what to bring, then ask if Thursday would work instead. By the time Wednesday’s results come back, the conversation has already moved on.

That’s the scenario in BookingDesk, Parlora’s example app for scheduling clinic appointments by voice. The clinic and patient records are fictional. You’ll find the source code and setup instructions in Run it yourself.

Start with a clean call

The calls use a fixed caller script synthesized in my voice. The assistant generates its replies live while the backend runs and writes to the database. Choose a model, press Play, or jump directly to the date correction. The two waveforms show the caller and assistant separately, and the activity panel follows the backend work as the call plays.

The demo deliberately waits 25 seconds for the first lookup, 1.2 seconds for the Thursday lookup, and 5 seconds to book. Those waits let you hear how the assistant handles questions and corrections while the backend is still working.

Keep the work aligned with the conversation

Listen to what happens around the date correction:

  1. Wednesday’s lookup starts. The assistant answers the preparation question while that task remains in progress.
  2. The caller asks for Thursday instead. BookingDesk interprets the correction, and Parlora tracks a replacement task revision. The new lookup can return while the old one is still running.
  3. Wednesday’s result arrives later. It is no longer current, so it is filtered before it can be returned to the voice model.

Wednesday’s availability can still be accurate and no longer answer the caller’s question. Parlora tracks which lookup is current. The earlier lookup can finish in the background, and Parlora filters its result before it reaches the voice model.

Who decides what?

ComponentResponsibility in this example
Speech providerListen to caller audio and generate the assistant’s spoken replies.
ParloraCoordinate audio and backend tasks, and deliver results for the current request.
JEV and ReqLLMJEV helps interpret caller intent. ReqLLM extracts details such as name and date of birth.
BookingDesk and JidoValidate the request and execute deterministic scheduling actions against SQLite.

BookingDesk looks up the patient by name and date of birth. Before searching for appointments, the assistant asks whether the insurance on file is still current.

Offered 10:15 AM or 2 PM, the caller says, “The morning one, please.” BookingDesk matches that choice to the only morning slot on offer and creates a proposal. The assistant reads back the exact appointment and asks for approval. BookingDesk checks that the proposal is still current and reserves the slot in a database transaction. If a request is retried with the same ID, BookingDesk returns the original result.

Once the booking is confirmed, the caller can opt in to a text reminder. The assistant reads back the last four digits and asks permission to send the reminder to that number. The backend saves the reminder for 24 hours before the appointment. If saving the reminder fails, the booking stays in place.

JEV’s interpretation and a speech model’s tool arguments are inputs to these decisions. Permission to change records remains in application code. The example source contains the policy, structured extraction, and Jido actions.

Then add a café background

The café calls use the same caller clips, booking workflow, and four voice models as the clean calls. This time, a café recording is mixed into the audio sent to the speech provider. It stays at a fixed level throughout the call, including while the assistant is speaking.

Run it yourself

Try BookingDesk with your own microphone. It records the call using fictional patient records and appointments. Text reminders are simulated; no SMS is sent. The microphone flow below was tested on macOS.

1. Get the example

From the directory where you keep your projects, clone Parlora and select the tested revision:

git clone https://github.com/hfiguera/parlora.git
cd parlora
git checkout 54446bbf8a7df2386eb5d77916f3a4de42cf96b5
cd examples/booking_desk

2. Install and verify

Install a compatible Elixir 1.18+/Erlang OTP 27+ pair and the native prerequisites for your operating system. Then, from examples/booking_desk, run:

mix deps.get --check-locked
mix test --warnings-as-errors

The tests run without API keys or paid model calls.

3. Set your API keys

The live call uses OpenAI for speech and structured extraction, and JEV for intent judgments. You need OpenAI and TypeSafe API accounts with available credit. Replace these placeholders with your keys in the same terminal:

export OPENAI_API_KEY="your-openai-key"
export TYPESAFE_API_KEY="your-typesafe-key"

Microphone mode does not require an ElevenLabs key.

4. Start a call

Use headphones, allow microphone access if prompted, and run:

PARLORA_PROVIDER=openai BOOKING_DATABASE=:memory: \
mix run run.exs "runs/microphone-$(date +%Y%m%d-%H%M%S)" clips --microphone

Keep clips in the command as a placeholder. BookingDesk uses your microphone in this mode, so you can run it without a clips directory or prerecorded caller audio.

The demo calendar has slots on November 4 and 5, 2026. Wait for the assistant’s greeting, then ask for Dr. Lee on November 4. When asked for your details, use Jamie Rivera, March 12, 1990, or Alex Morgan, July 24, 1985, then confirm the insurance on file. Both name and DOB must match a demo record.

To try the correction flow, change to November 5 while the lookup runs. Choose an offered time and approve the appointment readback. You can also opt into a simulated text reminder.

Press Enter to save the recording and stop. A final summary of outcome: stopped is normal. A completed booking appears as booked_appointments: 1; a saved reminder appears as simulated_reminders: 1.

Each call starts a fresh in-memory database. Its appointments and reminders disappear when it exits; the audio and report remain in the timestamped runs/microphone-… directory.
