Keep talking while we book it

A conversation can move faster than the work it starts. Follow a real Parlora session as the caller asks a question, changes the date, and confirms an appointment while Jido works in the background.

A caller asks for an appointment with Dr. Lee on Wednesday. While the calendar lookup runs, they ask what to bring. Then they change their mind: Thursday would be better.

The conversation has moved on, but Wednesday’s lookup is still working. When it finishes, the application needs to know whether that result still belongs in the conversation.

BookingDesk makes that coordination visible. The voice model listens and speaks, Parlora coordinates audio and backend tasks, and application rules decide what may actually change. The clinic and patient records are fictional; the speech connections, Jido actions, and SQLite writes are real.

Start with a clean call

These calls were recorded using a fixed caller script synthesized with ElevenLabs v4. The assistant generated its replies during each session, while backend actions and database writes executed. Choose a model, press Play, or jump directly to the date correction. The two waveforms show the caller and assistant separately, while the activity panel follows the backend work at the playhead.

The first availability lookup includes an intentional 25-second delay. The corrected lookup takes 1.2 seconds, and booking includes a 5-second delay. These injected waits create room for follow-up questions and corrections; they are not measurements of a production calendar service.

Keep the work aligned with the conversation

Listen to what happens around the date correction:

  1. Wednesday’s lookup starts. The assistant answers the preparation question while that task remains in progress.
  2. The caller asks for Thursday instead. BookingDesk interprets the correction, and Parlora tracks a replacement task revision. The new lookup can return while the old one is still running.
  3. Wednesday’s result arrives later. It is no longer current, so it is filtered before it can be returned to the voice model.

Wednesday’s availability may be factually correct and still be the wrong answer now. Parlora coordinates task revisions and result delivery so that the application can keep returning work aligned with the caller’s current request.

Speaking, interruption, and database execution have separate lifecycles. Clearing queued speech does not undo a booking. Replacing a search does not prove that its earlier backend operation stopped. The player shows that distinction: an obsolete lookup can keep running until its actual finish event.

Who decides what?

ComponentResponsibility in this example
Speech providerListen to caller audio and generate the assistant’s spoken replies.
ParloraCoordinate audio, independent backend tasks, revisions, result delivery, and session lifecycle.
JEV and ReqLLMInterpret bounded intent/readback questions and extract structured fields from caller speech.
BookingDesk and JidoValidate the request and execute deterministic scheduling actions against SQLite.

The assistant asks for name and date of birth, matches a fictional record, and confirms the insurer on file before searching. This is demo record matching and registration review, not production identity authentication or insurance eligibility verification.

Choosing a time creates a proposal; it does not book it. The assistant reads back the exact appointment and asks for approval. The application checks the current proposal and reserves the slot transactionally. Repeating a request ID returns its stored result instead of creating another booking.

After the verified booking, the caller can opt in to a reminder and confirm the cell number’s last four digits. The backend saves a simulated reminder for 24 hours before the appointment. No real SMS is sent, and a reminder failure leaves the booking intact.

JEV’s interpretation and a speech model’s tool arguments are inputs to these decisions. Permission to change records remains in application code. The example source contains the policy, structured extraction, and Jido actions.

Then add a café background

People also call from busy places. This second set mixes a continuous café recording into caller input before it reaches the speech provider, including while the assistant is talking. It uses the same caller clips and scheduling workflow, with a fixed background level.

Both sets exercise OpenAI GPT-Live-1, Phonic-1, Grok Voice 3.0, and Gemini 3.8 Live. Their adapters preserve different delegation and continuation protocols while using the same application policy. These are individual application runs, not a controlled model ranking.

Gemini’s café trial does not complete the booking. Its incoming transcriptions include background chatter, and the application loses the scheduling context. The failed trial is retained above; the clean Gemini recording completes the workflow. This trial shows what happened with this café background and setup. It does not establish how Gemini performs in other noisy conditions.

The background comes from moxobna’s CC0 coffeehouse recording.

Run it yourself

Try BookingDesk with your own microphone. It records the call using fictional patient records and appointments. Text reminders are simulated; no SMS is sent. The microphone flow below was tested on macOS.

1. Get the example

From the directory where you keep your projects, clone Parlora and select the tested revision:

git clone https://github.com/hfiguera/parlora.git
cd parlora
git checkout 114a6fcda04e49524ae65fe85e2a3d58b68a687f
cd examples/booking_desk

2. Install and verify

Install a compatible Elixir 1.18+/Erlang OTP 27+ pair and the native prerequisites for your operating system. Then, from examples/booking_desk, run:

mix deps.get --check-locked
mix test --warnings-as-errors

The tests run without API keys or paid model calls.

3. Set your API keys

The live call uses OpenAI for speech and structured extraction, and JEV for intent judgments. You need OpenAI and TypeSafe API accounts with available credit. Replace these placeholders with your keys in the same terminal:

export OPENAI_API_KEY="your-openai-key"
export TYPESAFE_API_KEY="your-typesafe-key"

Microphone mode does not require an ElevenLabs key.

4. Start a call

Use headphones, allow microphone access if prompted, and run:

PARLORA_PROVIDER=openai BOOKING_DATABASE=:memory: \
mix run run.exs "runs/microphone-$(date +%Y%m%d-%H%M%S)" clips --microphone

Wait for the assistant’s greeting before speaking. Ask for Dr. Lee on November 4, 2026. When asked for your details, use Jamie Rivera, March 12, 1990, or Alex Morgan, July 24, 1985, then confirm the insurance on file. Both name and DOB must match a demo record.

To try the correction flow, change to November 5 while the lookup runs. Choose an offered time and approve the appointment readback. You can also opt into a simulated text reminder.

Press Enter to save the recording and stop. A final summary of outcome: stopped is normal. A completed booking appears as booked_appointments: 1; a saved reminder appears as simulated_reminders: 1.

Each call starts a fresh in-memory database. Its appointments and reminders disappear when it exits; the audio and report remain in the timestamped runs/microphone-… directory.
